Landing Zone to Graph

What happens to one line of a CAD export between the moment it is dropped on a filesystem and the moment an investigator can traverse it. Three zones, one transformation definition, and two side channels that exist because the failure worth preventing is silent corruption rather than a crash.

The whole path

Solid edges carry records forward. The dotted edge running backwards is replay: given a bronze range and a mapping version, silver and gold are rebuilt from source bytes that were never modified.

What each zone guarantees

Bronze

Landing

Parquet + JSON manifest

The connector cuts the file into records and stops. It does not parse: the payload is the raw line, quotes and original date formats intact, because parsing is the mapping's job and keeping that line sharp is what lets one mapping serve a future Kafka feed of the same records.

Each record is wrapped with its source, connector instance, ingest time, source-asserted time, content hash and offset. The manifest is the commit: written last by atomic rename, so a crash leaves an orphaned data file rather than a half-readable batch.

BronzeStore has no update, delete or truncate method. "Never mutated by platform logic" is enforced by the operations not existing.

Silver

Canonical

Iceberg, one table per type

Every hop validates on the way in and on the way out. The two catch different failures: an input violation means the source changed underneath the mapping, an output violation means the mapping is wrong. Running only one leaves half the failure surface unwatched.

Identity is assigned here, and how depends on the entity. An incident has an authoritative key in its source, so its identity is derived. A person is a real thing several sources describe differently, so its identity comes from resolution.

Table schemas are derived from the canonical model, so a table cannot drift from the model that writes to it.

Gold

Projections

Neo4j property graph

An entity becomes a node keyed by its canonical identity. A two-role association becomes a relationship, not an intermediate node — NIEM's association structures are already graph edges, and reifying them would be exactly the flattening the model went to trouble to avoid.

An association whose endpoints are missing fails the run rather than vanishing. An association in silver with no edge in gold is a divergence, and a quietly wrong graph is worse than a stopped one.

Every write MERGEs on canonical identity, so applying the same changes twice leaves the same graph. Replay depends on it.

One row, step by step

The two side channels

Both hang off every hop, and the split between them is the whole redaction design. One travels to dashboards and log aggregators. The other holds evidence.

Event stream

Structured, countable, and carrying the shape of a value rather than the value.

DOB: pattern expected ^\d{2}/\d{2}/\d{4}$ found String(len=10, shape=####-##-##)

Enough to diagnose a source changing its date format. Safe to index.

Quarantine

Values intact, under the same access controls as bronze, so the record can be reprocessed.

"NAME_FULL": "OKAFOR, ADA" "DOB": "1979-12-01" "DL_NUM": "R5540021"

Never in a log directory. The date of birth exists in exactly one of these two panels.

Ten source rows produce thirty canonical records, six person clusters and eight incidents. The same mapping definition runs unchanged in batch and in streaming, producing identical output — the criterion the specification says validates the whole architectural bet.

Not yet built: replay is the last unproven criterion. Search and warehouse projections are Phase 2 and Phase 3. Phase 1 has no user interface by design.
