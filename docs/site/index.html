NIEM Integration Platform

Decisions, and what they cost

A platform for moving criminal justice records between agencies. Most of what follows is a record of things deliberately made impossible — because in this domain, the failures that end a product are the ones nobody chose.

  • 27 decisions recorded
  • 428 tests
  • Phase 1 complete

The shape of it

Source data lands byte-for-byte and is never rewritten. Everything downstream is a function of that landing and a versioned mapping, so it can be deleted and reproduced exactly. Every hop between the two is gated by a contract that quarantines what does not fit rather than passing it on.

NIEM is the canonical form throughout, and every provenance claim in the model is resolved against a published NIEM 6.0 release when the code is generated. A mapping is data, not code: a domain steward edits it and redeploys without a platform build.

What is made impossible

Each of these is narrower than the obvious design. Each was chosen because the wider version fails in a way that cannot be explained afterwards.

A deployment holds one agency's data and refuses everyone else's

Shared logical multi-tenancy is not built and not supported. There is no tenant column and no filter to remember, because there is no cross-tenant read path at all. A store records the agency it belongs to the first time it stores anything and refuses another's on open — before a single record is written, because the landing zone is append-only and an interleave cannot be undone.

Logical isolation is only ever as good as every read path remembering to filter. That check must be correct in every query, every projection and every new feature, forever. One omission is an unauthorised disclosure between agencies.

“Your records are in your own database” is something an agency's counsel can verify in a sentence. “Every query filters correctly by tenant” is a promise about code that a lawyer cannot audit and a court will not take on faith.

Prevents Two agencies' records mixing in one store, discovered later, in data that by design is never rewritten.

ADR 0026

Linking a person across agencies is an assertion, never a coincidence

Identity is seeded with the agency that minted it. The same person, known to a county and to the state by the same licence number, resolves to two distinct identities. Connecting them is a deliberate act, recorded with a who, a when and a why.

Before this, both agencies derived the same identifier and their records merged — silently, as a property of a hash function, with no log line and no notification.

An automatic merge across jurisdictions is the failure that ends a criminal justice product. It cannot be explained to a court, it cannot be retracted cleanly, and nobody can say who decided it. A deliberate link can be reviewed, disputed and withdrawn.

Prevents Two people becoming one, or one person's record following them between agencies, because a hash collided.

ADR 0025

If the disclosure cannot be recorded, the disclosure does not happen

Every cross-agency release is written to an append-only log before anything moves: who asked, under what authority, what they got, what was withheld and why, and who decided. The ordering is structural — a caller cannot release first and log afterwards.

The consequence is deliberate. An agency that cannot write to its own audit log has lost the right to release data until it can, because it can no longer say what it released.

The log names records and has nowhere to put one. An audit log containing the data it audits is a second copy of that data, usually with weaker access controls and longer retention — so the log of who saw what becomes the easiest place to see it. Refusals are recorded with the same weight as releases, because “did anyone try to get this?” is the first question asked when misuse is suspected.

Prevents A release with no record of it, produced by exactly the conditions an auditor cares about — a crash, a full disk, a partition.

ADR 0026

Some responses may not be kept, so they are never landed

This does not follow from architecture. It follows from law. Responses from criminal history systems are frequently not retainable: the rules permit use for the purpose at hand and forbid keeping a copy.

A platform whose landing zone is append-only and permanent would create an unlawful retention by doing the obviously correct thing. So a connector declares whether its records may be kept, with no default — a default would be “keep it”, and an author who had not considered the question would land data unlawfully. A TRANSIENT source is refused at the point of landing, not filtered afterwards.

Its only durable trace is the disclosure record, which is not a coincidence: what you are permitted to keep about a non-retainable response is precisely the fact that you requested it.

Prevents An unlawful retention created by a correct-looking default, in a store that cannot delete.

ADR 0027

One validator, and one path into canonical

The authoring surface owns no validation logic. It calls the same loaders the runtime calls, so a mapping the editor accepts is a mapping the pipeline will load. Two validators for one artifact format would drift, and the drift would surface at deploy.

The same applies to arrival. Push, poll and live query are properties of a connector, not different pipelines — all three pass the same contract-gated hops. Two ways into canonical means one of them is not validated, and given what gets integrated, it would be the one carrying criminal history from a state system.

Prevents A second, quieter route into the canonical model that nobody remembered to check.

ADR 0021 · ADR 0027

Records never print their values

A canonical record's toString shows its type and field names and no data. Contract violations carry a redacted shape — ###-##-####, never the number. The mapping advisor that proposes how a column should map is given names, types and those shapes, and its context type has no field capable of holding a value, so no implementation can leak one.

That constraint turns out not to cost anything. Knowing a column is always two digits, a slash, two digits, a slash and four digits is what picks the right date transform and its pattern. Knowing whose date of birth it is adds nothing.

Prevents Personal data reaching a log, a terminal, a screenshot, or a model, by way of a debug line nobody thought about.

ADR 0015 · ADR 0023

Provenance is checked, not asserted

Every NIEM reference in the canonical model is resolved against a published NIEM 6.0 release when the code is generated, from manifests committed to the repository so an air-gapped build can verify its own citations. A model whose citations cannot be checked does not build.

An unverified provenance does not announce itself. It is well-formed, plausible, and reads exactly like a citation — so it survives review, gets copied into the next model, and is discovered by an integrator whose data will not exchange.

Prevents A model that claims to be NIEM-conformant and is not, found by the party trying to exchange with it.

ADR 0011

The authoring surface has no front door of its own

It writes the mappings and contracts that decide what the pipeline does with an agency's data, so write access to it is write access to the platform's behaviour. It binds to loopback inside its pod and ships with no Service, no Ingress and no NodePort.

The only way in is kubectl port-forward, which routes every access through the cluster's API server — authenticated, authorised against RBAC, and audited. The authentication it does not have is supplied by a component the agency's security team has already reviewed, and it cannot be bypassed by adding a Service later, because a Service would not reach it.

Prevents An unauthenticated write path to the platform's behaviour, reachable by anything on the pod network.

ADR 0024

What this costs

Stated here rather than left to be discovered. A design document that lists only its strengths is a sales document.

It is only safe alongside managed operation

Ten small agencies each running their own deployment means ten patch cadences, and the unpatched one is the real attack vector — far more than architectural leakage ever is. The answer for an agency that cannot run infrastructure is a deployment operated for them, not a slice of somebody else's database.

Failure to connect is a harm too

An investigator who never learns the person in front of them is wanted in the next county has also been failed by the system, and that is the harm NIEM exists to address. Physical isolation raises the cost of connecting agencies, so federation has to be good, cheap and routine — or this trades a disclosure risk for an investigative one. Confidentiality failures make the news; connection failures make the inquiry.

A non-retainable source cannot be replayed

Rebuilding everything from what arrived depends on having kept what arrived. Where nothing may be kept, replay is not available — and no surface may offer it for such a source, because offering it would be a lie about what the system can prove.

Federation is designed, not built

The identifiers, the disclosure record and the boundary rules exist so that federation is built to them rather than retrofitted with them. The exchange itself, and the trust model underneath it, are still ahead.

What the checks found

Each of these passed every other test the platform had, and was found by verifying a claim rather than by exercising a feature.

Three wrong NIEM citations

Resolving the model against a real NIEM 6.0 release found that nc:PersonSexCode is the right name in the wrong namespace, nc:DriverLicenseIdentification does not exist anywhere in NIEM 6.0, and an association modelled as a platform extension had a real NIEM type all along — so the platform was carrying an extension it did not need, with the interoperability cost that implies.

An ingest that stored nothing

The pipeline landed source data, mapped it, and discarded the result, while printing a line that had been true when it was written and false for a long time afterwards. Every unit test passed, because none of them asked where the records went. It was found by running the container and reading the output.

A canonical store that could only be written once

The catalogue could be created and never reopened, so the second scheduled ingest would have failed — the normal case, every fifteen minutes. It was invisible because every test used a fresh catalogue.

Still open

Questions with real answers that are not yet owed. Recorded so that nobody resolves them by accident.

Whether a non-retainable response may be cached for the life of a single investigation, and by what authority — a question for counsel per jurisdiction, which the platform should be able to express either way rather than assume. Whether a shared deployment is ever permitted for agencies whose data classifications differ. And the trust model underneath federation itself.

Full reasoning for every decision is in docs/decisions/, one file each, with the consequences accepted and the alternatives rejected.
