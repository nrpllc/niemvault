NIEM Integration Platform

Decisions, and what they cost

A platform for moving criminal justice records between agencies. Most of what follows is a record of things deliberately made impossible — because in this domain, the failures that end a product are the ones nobody chose.

  • 27 decisions recorded
  • 428 tests
  • Phase 1 complete

The shape of it

Source data lands byte-for-byte and is never rewritten. Everything downstream is a function of that landing and a versioned mapping, so it can be deleted and reproduced exactly.

Every hop between the two is gated by a contract that quarantines what does not fit rather than passing it on. NIEM is the canonical form throughout, and every provenance claim in the model is resolved against a published NIEM 6.0 release when the code is generated. A mapping is data, not code: a domain steward edits it and redeploys without a platform build.

The four claims

Each is enforced in code, not asserted in documentation.

No ambient access

Nothing is visible across an agency boundary because it happens to sit in the same database, bucket or network. There is no cross-tenant read path to secure, because there is none.

A store refuses data that is not its tenant's

Enforced when written, not filtered when read.

Every cross-agency disclosure is a record

Who asked, what was returned, when, and under whose authority — written before anything moves.

Absence is reported

A federated answer says which participants did not respond. A federation that quietly under-answers teaches investigators that a clean result means nothing was found.

Full reasoning for every decision is in docs/decisions/, one file each, with the consequences accepted and the alternatives rejected.

Isolation and trust

What is made impossible

Each of these is narrower than the obvious design. Each was chosen because the wider version fails in a way that cannot be explained afterwards.

A deployment holds one agency's data and refuses everyone else's

Shared logical multi-tenancy is not built and not supported. There is no tenant column and no filter to remember, because there is no cross-tenant read path at all. A store records the agency it belongs to the first time it stores anything and refuses another's on open — before a single record is written, because the landing zone is append-only and an interleave cannot be undone.

Logical isolation is only ever as good as every read path remembering to filter. That check must be correct in every query, every projection and every new feature, forever. One omission is an unauthorised disclosure between agencies.

“Your records are in your own database” is something an agency's counsel can verify in a sentence. “Every query filters correctly by tenant” is a promise about code that a lawyer cannot audit and a court will not take on faith.

Prevents Two agencies' records mixing in one store, discovered later, in data that by design is never rewritten.

ADR 0026 — isolation by construction

Linking a person across agencies is an assertion, never a coincidence

Identity is seeded with the agency that minted it. The same person, known to a county and to the state by the same licence number, resolves to two distinct identities. Connecting them is a deliberate act, recorded with a who, a when and a why. 

co.riverton.pd    co.riverton.pd/person:a602971dbe04f16c7a04f4fd
st.colorado.cbi   st.colorado.cbi/person:21c0818c2a447d1753c72d5c

Before this, both agencies derived the same identifier and their records merged — silently, as a property of a hash function, with no log line and no notification.

An automatic merge across jurisdictions is the failure that ends a criminal justice product. It cannot be explained to a court, it cannot be retracted cleanly, and nobody can say who decided it. A deliberate link can be reviewed, disputed and withdrawn.

Prevents Two people becoming one, or one person's record following them between agencies, because a hash collided.

ADR 0025 — tenancy and federation

If the disclosure cannot be recorded, the disclosure does not happen

Every cross-agency release is written to an append-only log before anything moves. The ordering is structural — a caller cannot release first and log afterwards. 

2026-03-11T14:02:11Z  st.colorado.cbi → co.riverton.pd
PARTIAL   2 released, 1 withheld
reason    one record sealed under CRS 19-1-304 (juvenile)
under     CRS 24-72-305; CBI-Riverton MOU 2025-11
decided   sgt.k.oyelaran@riverton.pd.gov

An agency that cannot write to its own audit log has lost the right to release data until it can, because it can no longer say what it released.

The log names records and has nowhere to put one. An audit log containing the data it audits is a second copy of that data, usually with weaker access controls and longer retention — so the log of who saw what becomes the easiest place to see it. Refusals are recorded with the same weight as releases, because “did anyone try to get this?” is the first question asked when misuse is suspected.

Prevents A release with no record of it, produced by exactly the conditions an auditor cares about — a crash, a full disk, a partition.

ADR 0026 — the disclosure record

Some responses may not be kept, so they are never landed

This does not follow from architecture. It follows from law. Responses from criminal history systems are frequently not retainable: the rules permit use for the purpose at hand and forbid keeping a copy.

A platform whose landing zone is append-only and permanent would create an unlawful retention by doing the obviously correct thing. So a connector declares whether its records may be kept, with no default — a default would be “keep it”, and an author who had not considered the question would land data unlawfully. A TRANSIENT source is refused at the point of landing, not filtered afterwards.

Its only durable trace is the disclosure record, which is not a coincidence: what you are permitted to keep about a non-retainable response is precisely the fact that you requested it.

Prevents An unlawful retention created by a correct-looking default, in a store that cannot delete.

ADR 0027 — foreign feeds and federation

The authoring surface has no front door of its own

It writes the mappings and contracts that decide what the pipeline does with an agency's data, so write access to it is write access to the platform's behaviour. It binds to loopback inside its pod and ships with no Service, no Ingress and no NodePort.

The only way in is kubectl port-forward, which routes every access through the cluster's API server — authenticated, authorised against RBAC, and audited. It cannot be bypassed by adding a Service later, because a Service would not reach it.

Prevents An unauthenticated write path to the platform's behaviour, reachable by anything on the pod network.

ADR 0024 — the authoring surface is not exposed

What this costs

Stated here rather than left to be discovered. A design document that lists only its strengths is a sales document.

It is only safe alongside managed operation

Ten small agencies each running their own deployment means ten patch cadences, and the unpatched one is the real attack vector — far more than architectural leakage ever is. The answer for an agency that cannot run infrastructure is a deployment operated for them, not a slice of somebody else's database.

Failure to connect is a harm too

An investigator who never learns the person in front of them is wanted in the next county has also been failed by the system, and that is the harm NIEM exists to address. Physical isolation raises the cost of connecting agencies, so federation has to be good, cheap and routine — or this trades a disclosure risk for an investigative one. Confidentiality failures make the news; connection failures make the inquiry.

A non-retainable source cannot be replayed

Rebuilding everything from what arrived depends on having kept what arrived. Where nothing may be kept, replay is not available — and no surface may offer it for such a source, because offering it would be a lie about what the system can prove.

Federation is designed, not built

The identifiers, the disclosure record and the boundary rules exist so that federation is built to them rather than retrofitted with them. The exchange itself, and the trust model underneath it, are still ahead.

Architecture

Three zones and one rule

The rule is that everything except the first zone is derived, and can be deleted and reproduced exactly. That is what makes the rest of the design possible to check.

The zones

Bronze

What a source actually sent, byte-for-byte, with a complete envelope: where it came from, when it landed, what the source asserted about it, and a content hash. Append-only. Never rewritten, because it is the only thing nothing else can reconstruct.

Silver

Canonical records in NIEM-derived types, on Iceberg. Derived, and therefore droppable — the store carries a drop for exactly that reason, and bronze does not.

Gold

Projections built for how they are queried: a graph for connections, later a search index and a warehouse. Rebuildable from silver, which is rebuildable from bronze.

Contracts on every hop

A hop is one step from one shape to another, and each is gated in both directions. A record that does not match its contract is quarantined and emits a structured violation event — it is not dropped, and it does not halt the pipeline. One bad record from a source that changed its date format overnight must not stop an agency's feed.

A contract is a versioned artifact next to the mapping it gates, and the platform checks that the two agree: a field the contract requires that no step produces is reported before deploy, not discovered as a quarantine filling with the entire feed.

Mappings are data

A mapping is a YAML artifact declaring a decoder and a sequence of hops. Changing it and redeploying changes what the pipeline produces; it does not require a platform build. The same mapping definition runs unchanged in batch and streaming, producing identical canonical output — the acceptance criterion that validates the whole architectural bet.

They are authored on a canvas that draws the field-level flow: source columns in, transforms, canonical fields out, and what decides the record's identity. Edits patch the artifact line by line rather than regenerating it, because a mapping's comments carry the reasoning behind its steps and a round trip would erase them.

Identity

Some records carry an authoritative key from their source — an incident number assigned at call creation and never reused — and their identity is derived from it. People do not, so they go through resolution: normalised keys in tiers, a licence number weighted differently from a name and date of birth, and a cluster identifier that is stable across runs so a replay reaches the same answer.

That identifier is seeded with the agency, which is what makes it meaningful outside the database that minted it — and what makes an accidental cross-agency merge impossible.

Integrating

Two boundaries, one path in

A city may need criminal history it does not hold. The platform does not get to dictate the other end's protocol, schema, or whether it speaks NIEM at all — but NIEM remains the canonical form regardless.

Foreign integration

A state, federal or vendor system. Arbitrary protocol, arbitrary schema, arbitrary interaction model. Nothing is assumed and everything is configuration. This is where the mess lives, deliberately and by itself.

A foreign system may speak NIEM, a local variation of it, or something unrelated. That is a mapping problem, and mapping is what this platform is for. It is never a reason to alter the canonical model, add a field the model does not have, or accept a record that did not pass a hop contract.

Federation

Between tenants running this platform: one interface, speaking the canonical model and NIEM. No negotiation and no per-partner variation, because both ends are ours.

Separating the two is what stops the first eroding the second. An integration that cannot be made to fit federation is a foreign integration; it does not become a dialect of federation. Every accommodation added to federation is one that every future partner inherits.

How records arrive

Push, poll and live query are properties of a connector, not different pipelines. All three land through the same contract-gated hops. Two ways into canonical would mean one of them is not validated, and given what gets integrated, it would be the one carrying criminal history from a state system.

A connector also declares whether its records may be kept, with no default. See Isolation for why that is a legal question rather than an architectural one.

The catalogue

Every source carries a glossary of its own vocabulary, because the half that matters cannot be derived from anything. NIEM provenance answers what standard does this field come from. A glossary answers what does this agency call it, and what did they mean. 

DL_NUM  →  Person.driverLicenseId
  Driver licence number as recorded. The literal UNK appears where
  none was provided, and must not be treated as an identifier — it
  would resolve every such person to one cluster.

That fact is not in the data, the column name, or the NIEM reference. It exists in the head of whoever wrote the mapping until they write it down. Gaps are reported rather than skipped: a catalogue listing only its documented terms would tell an agency their source is fully understood.

Operating

One image, both delivery modes

Air-gapped delivery is mandatory, not a fallback. Many criminal justice environments will not permit outbound connectivity, so there is no on-prem-only code path — the same artifact the vendor cloud pushes is what an agency loads from a tarball.

The operator's commands

niem validate   are the mappings and contracts coherent
niem author     open the authoring canvas
niem run        land a source and map it
niem replay     rebuild silver and the graph from bronze alone
niem inspect    what has landed, and is it intact
niem catalogue  what a source sends and what it means

Every command that destroys says what it is about to destroy first. replay drops and rewrites the canonical tables it produces, so it prints the current record count per table before touching anything, and --dry-run stops there.

Credentials

Never a command-line option. An option is written to shell history and visible in the process list to every user on the machine, which is not a defensible way to handle credentials for a system holding criminal justice data. They come from the environment, and in Kubernetes from Secrets — never from chart values, which appear in helm get values and in whatever stores the release history.

In a cluster

Ingest runs as a CronJob, because the Phase 1 connector is a file drop: a job that lands what arrived and exits, not a service whose health is unrelated to whether any data moved. Replay ships as a suspended Job, since it is not something an install should perform.

Bronze gets a persistent volume marked to survive uninstall. Losing it loses the ability to replay, which is the platform's central claim, and a routine command should not be able to do that.

The image carries the platform and nothing else. Domain modules are versioned content on their own release cycle and are mounted, not baked in — otherwise a platform patch would force a content release, and the reverse.

Proof

What the checks found

Each of these passed every other test the platform had, and was found by verifying a claim rather than by exercising a feature.

Three wrong NIEM citations

Resolving the model against a real NIEM 6.0 release found that nc:PersonSexCode is the right name in the wrong namespace, nc:DriverLicenseIdentification does not exist anywhere in NIEM 6.0, and an association modelled as a platform extension had a real NIEM type all along — so the platform was carrying an extension it did not need, with the interoperability cost that implies.

An ingest that stored nothing

The pipeline landed source data, mapped it, and discarded the result, while printing a line that had been true when it was written and false for a long time afterwards. Every unit test passed, because none of them asked where the records went. It was found by running the container and reading the output.

A canonical store that could only be written once

The catalogue could be created and never reopened, so the second scheduled ingest would have failed — the normal case, every fifteen minutes. It was invisible because every test used a fresh catalogue.

A mapping that would have quarantined everything

A contract requiring a field no step produced loaded perfectly and would have rejected the entire feed — quietly, because bad data must not halt the pipeline. Now reported before deploy, and drawn on the canvas as a hollow slot.

The acceptance criteria

All seven proven in tests. The seventh is the one that validates the bet.

Questions with real answers that are not yet owed. Recorded so that nobody resolves them by accident.
